Contrat public options/sous-systèmes version 1 accepté dans CorvusAPI #5 ; ABI0 et anciennes structures préservées. Header canonique publié dans include/corvusapi.h, règles normatives dans docs/CONFIGURATION.md.
Core SDK : corvuscore_link_create, corvuscore_link_run_frame et corvuscore_link_destroy disponibles pour GB/GBC2 et GBA2..4. L'adaptateur v1 expose deux jeux du même module et une image côte à côte. Reset groupé préparé avant commit, batteries et générations préservées ; aucun état complet de paire, donc serialize_size0 en link officiel. Les deux files audio sont drainées, même si une seule est audible.
Options exposées : GB palette3, GBC couleurs de compatibilité14, GBA save_type7/RTC3, audio link3 pour tous. Pas de faux BIOS par chemin, modèle matériel ni capteur solaire dans cette version de l'extension.
Frontend engine remplace une instance à chaque ouverture ; les options doivent être persistées par core/key/valueID et réappliquées à tous les candidats. Garder l'ancien suffixe de format état0.14.1 même si fournisseur0.15.0, tant que format solo inchangé.
Android refuse les hard links vers app_data_file (AVC denied link observé sur API29). Le backup d'options doit être copié et fsync dans .bak.new, puis renommé atomiquement en .bak ; une copie partielle ne doit jamais devenir un fichier de récupération. Le test natif remplace link() par EPERM pour couvrir les modifications répétées.
P1 sauvegarde historique <id>.sav ; P2 <second_id>-link-p2.sav protège même ROM sur les deux joueurs. Toute persistance échouée conserve instance active ; pas d'acquittement sans commit durable par slot.
RA : extension mémoire sans index joueur ; désactiver pendant session multiple et conserver compte/file d'envois.

Distribution autonome : CorvusRepository compile les six modules NDK directement depuis CorvusCore qualifié, sans checkout frontend, Gradle ni signature APK. Les autres développeurs proposent une déclaration providers, des sources/licence/CI relues et un catalogue dans leur espace de noms. Les imports contrôlent le commit du tag, la CI exacte et les ZIP/ELF/SHA avant centralisation. Aucun fournisseur de démonstration publié.
Le lot central v0.15.1 contient les moteurs 0.15.0 recompilés, sans modifier les anciennes archives frontend. Les six ZIP publics sont identiques aux fichiers Actions standalone utilisés pour les essais Android.
GitHub CLI fournit apiUrl dans gh release view, pas databaseId. Les assets de brouillon ont une URL temporaire untagged-hex : n'accepter cette forme que pour draft=True avec origine, nom, empreinte et taille exacts, puis exiger le vrai tag après publication. Les 53 tests et la publication réelle couvrent ces cas.
La session cloud permet les écritures API/branches, mais ses uploads directs ont reçu 401 ; le workflow avec GITHUB_TOKEN a réalisé la publication. Aucun secret APK supplémentaire ni connexion interactive. La politique GitHub interdit au jeton Actions de créer une PR : le publisher prépare la branche, lance sa CI explicite et fournit la comparaison. Le mainteneur ouvre puis examine la PR ; aucun contournement de revue ni fusion automatique.
